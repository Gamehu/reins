# Java 审查参考

适用于 `.java` 改动。格式类问题以项目配置的 formatter 为准，不作为审查项。

## 优先级

1. **可执行检查**：`scripts/p3c-check.sh`（P3C 2.1.1）以及项目自身配置的静态检查（如 PMD、Checkstyle、SpotBugs）。结果直接采用，不要求审查者重复判断。
2. **项目约定**：项目说明文件中的规则（如作者标签、DTO 写法、分层与模块边界、测试基础设施）。
3. **Google Java Style**：命名、Javadoc、导入、格式的默认依据。
4. **P3C 2.1.1**：仅在 1–3 没有覆盖、且 P3C 的规则合理时采纳。

冲突时以更靠前的一条为准，并在报告里注明“按 X 处理”。

## Google Java Style 要点（审查者需要检查）

- 类名 UpperCamelCase，方法和变量 lowerCamelCase，常量 UPPER_SNAKE_CASE。
- 公共类型和公共方法有 Javadoc，首句是摘要；参数、返回值、异常按需写 `@param`、`@return`、`@throws`。
- 每个顶层类型只放在一个文件中。
- 不要用通配符导入。
- 注释讲“为什么”，不复述代码。

## P3C 规则的采纳表

| P3C 规则 | 处理 | 说明 |
|---|---|---|
| 常量应全大写并下划线分隔 | 采纳 | 与 Google 一致 |
| 魔法值（字符串、数字） | 采纳（生产代码） | 测试代码中的魔法值只作提示，不阻断 |
| `@Transactional` 需指定 `rollbackFor` | 采纳 | Spring 默认只对运行时异常回滚，显式声明更稳妥 |
| 类注释需包含 `@author` | 按项目约定 | 项目要求作者标签时采纳，否则不列入 |
| `equals` 的常量写在前面 | 采纳 | 避免空指针 |
| 测试类命名后缀 | 按项目约定 | 以项目现有多数写法为准，要求统一 |
| 手动创建线程池 | 采纳 | 应使用受管的 executor，明确容量、命名和拒绝策略 |
| 格式、缩进、行宽 | 不采纳 | 以 Google 和项目 formatter 为准 |

## P3C 的覆盖缺口

- PMD 6.15 无法解析 `record` 等较新语法。这些文件 P3C 不检查，审查者必须人工覆盖其字段注释、命名和不变量。
- 脚本退出码 `3` 会列出未解析文件，报告的“覆盖范围”一节需要写明。

## 审查时的额外检查

- 事务方法内是否有外部调用（HTTP、消息、其他服务），失败时数据库状态是否一致。
- 循环中是否有逐条数据库查询（N+1）。
- 异常：不要吞异常，不要捕获 `Exception` 后只打印 `printStackTrace`，日志不得包含口令或完整 token。
- `record` 和自动生成的 `toString()` 是否会暴露口令、token 等敏感字段。
- 跨模块调用是否遵守项目规定的边界（接口、事件），而不是直接依赖其他模块的内部实现。
- 已执行过的数据库版本化迁移不得直接修改，变更应新增迁移文件。
