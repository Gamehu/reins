# TypeScript / React 审查参考

适用于 `.ts` 与 `.tsx` 改动。格式类问题以项目配置的 formatter 为准，不作为审查项。

## 优先级

1. **可执行检查**：项目配置的 lint 与类型检查（如 ESLint、`tsc --noEmit`）。结果直接采用。
2. **项目约定**：项目说明文件中的前端规则与目录分包约定。
3. **下列默认规则**与 **Google TypeScript Style**：项目没有另行规定时采用。

冲突时以更靠前的一条为准，并在报告里注明。

## 默认规则（项目未另行规定时检查）

- 函数组件优先，使用 Hooks；不写 class 组件。
- 类型定义方式（`interface` / `type`）全仓统一，不混用。
- 优先联合类型而非 `enum`；状态机用判别联合。
- 不用 `any`：边界用 `unknown` 加类型守卫；`switch` 穷尽检查用 `never`。
- 自定义 Hook 显式声明返回类型，不依赖推断。
- 包装原生元素时 `extends` 原生属性类型，并用 `...rest` 透传。
- 加载或错误状态用 early return，减少嵌套。
- 列表 `key` 使用稳定唯一 ID，禁止数组下标。
- 业务逻辑放 hooks 或 services，展示组件保持纯净。
- 使用 `const`、`let`，禁止 `var`；优先 `?.` 与 `??`。
- 导出的函数和组件有 TSDoc/JSDoc；不要重复抄写 TypeScript 类型。

## Google TypeScript Style 要点

- 导出符号优先具名导出（以项目现状为准，不要批量改动已有代码）。
- 注释使用 `/** ... */` 文档注释，首句说明行为。
- 不使用 `namespace`，不使用 `@ts-ignore`（必要时用 `@ts-expect-error` 并附原因）。

## 边界与分包

- 遵守项目已配置的模块边界规则（lint 规则或说明文件）。
- 需要跨模块共享的代码，应建议下沉到项目的公共目录，而不是复制。

## 审查时的额外检查

- Effect 的依赖数组是否完整，是否存在不必要的 Effect（能在渲染期计算的值不要放进 state 与 Effect 同步）。
- 异步请求是否处理了失败、取消和卸载后的 setState。
- 是否有硬编码的接口地址、密钥或口令。
- 是否为了“以后可能用到”引入了通用组件或 Hook，只有一处使用时应直接内联。
